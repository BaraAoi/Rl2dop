# Rl2dop — экономика поселений для Minecraft 1.21.1 (Fabric)

Мод про живую экономику: три номинала монет и кошелёк, рынок с плавающими ценами, NPC с
профессиями, ратуша с постройками и табличками нужд, казна, репутация и стража. Всё считается
**на сервере**, клиент только рисует.

Реальные проверки в CI: `settle_spawn` → постройки, `settle_build`, `give_coins`, `wallet`,
`spawn_npc`, `price_set`, `shelf_add`, `shop_marker`, `settle_bind` + **перезапуск сервера** на том же
мире. Из лога последнего зелёного прогона:

```
§aПоселение «§fSmokeTown§a» создано. Ратуша: §f0, -59, 0§a, постройка §f100%
§aРатуша, рынок и лавки поселения §fSmokeTown§a: постройка §f100%§a, точка магазина §f5, -59, 0
§cКошелёк открывается только из игры (нужен игрок).        # консоль — аккуратное сообщение, без падения
§7  казна=900м  NPC=4  постройка=100%  лавка=0, -59, 0  табличек=3
§7  minecraft:bread: сток=64 цена=5.00 спрос=0
§7загружено NPC рядом: 8 [Лина/cook/smokevillage, Дитрих/lumberjack/smoketown, ...]
=== ошибки/исключения (оба запуска) ===        (пусто)
```

CI покрывает серверную часть (строительство, точки, персист). Клиентское (окна без блюра,
экран кошелька, иконки товаров) проверяется только руками в игре — чек-лист ниже.

> **Статус:** собран по шагам 0–11 из техзадания. Мирогенерация и «красивая» генерация
> поселений не начаты намеренно (по плану — в самом конце), вместо неё привязка к ванильным
> деревням командой `/settle_bind`.

### Установка

1. Minecraft **1.21.1**, [Fabric Loader](https://fabricmc.net/use/installer/) ≥ 0.16.
2. Положить в `.minecraft/mods`:
   - `rl2dop-latest.jar` (из ссылки выше; внутри он уже с номером версии),
   - [Fabric API](https://modrinth.com/mod/fabric-api) для 1.21.1.
3. Запустить. При первом старте создаётся `config/rl2dop.json`.

Сервер: то же самое, мод нужен и на сервере, и на клиенте (есть HUD и торговый экран).

## Быстрый старт (2 минуты)

```mcfunction
/settle_spawn Тестовый_город     # поселение + ратуша, лавка и склад прямо на этой точке
/settle_bind                     # ИЛИ привязка к ванильной деревне (ищет колокол в 48 блоках)
/give_coins 200                  # напечатать монеты (кошелёк выдаётся автоматически)
/wallet                          # открыть кошелёк (можно и ПКМ по предмету «Кошелёк»)
/spawn_npc farmer                # заспавнить фермера
/spawn_npc trader Ганс           # торговец с именем
/shop_open                       # открыть торговый экран (или ПКМ по торговцу)
/market_dump                     # что с ценами
```

Дальше просто подожди: фермер носит зерно на склад, повар печёт хлеб из зерна,
торговец продаёт, стража получает зарплату из казны, NPC покупают еду и тратят монеты.

## Как работает экономика

### Деньги: три номинала и кошелёк

| Предмет | Ид | Номинал в бронзе |
|---|---|---|
| Бронзовая монета | `rl2dop:bronze_coin` | 1 |
| Железная монета | `rl2dop:iron_coin` | `coinIronValue` (по умолчанию 10) |
| Золотая монета | `rl2dop:gold_coin` | `coinGoldValue` (по умолчанию 100) |
| Кошелёк | `rl2dop:wallet` | хранит все три номинала в одном предмете |

* **Единая единица счёта — бронза.** Все цены, зарплаты, казна и репутационные формулы работают в
  бронзе, поэтому номиналы — только удобство переноски, а не отдельная валюта.
* Монеты лежат в инвентаре предметами, а в кошельке — числом в компоненте `custom_data`
  (`bronze` / `iron` / `gold`). Кошелёк — обычный предмет: его можно отдать, потерять, положить в сундук.
* Любая выдача/списание приводит набор к **каноничному** виду (сначала золото, потом железо,
  потом бронза): 100 бронзы = 1 золото, 10 бронзы = 1 железо. Команда `/wallet change` разменивает
  лишнее, `/wallet deposit` сгребает монеты из карманов, `/wallet withdraw` достаёт их обратно.
* Сервер при каждой сделке пересчитывает «кошелёк + карманы» целиком, поэтому перелить деньги
  из кошелька в монеты и назад, чтобы напечатать лишнее, нельзя.
* У NPC кошелёк — число в бронзе (`/npc_list`), при смерти выпадает реальными монетами номиналами.
* **Миграция:** предмет `rl2dop:coin` из ранних версий не удалён, чтобы не сломать старые миры.
  При входе игрока его старые монеты меняются на бронзу 1:1 (сумма не меняется), а монеты в сундуках
  можно обменять самому — ПКМ по старой монете. В креативе старый предмет не показывается.
* **Эмиссия** (`minted`) считается в `EconomyState` и ограничена `mintLimit` из конфига.
  Напечатать больше лимита нельзя — `/give_coins` просто выдаст меньше.
* Казна поселения — отдельный счёт в `Settlement#treasury`. Зарплаты и скупка идут **из казны**,
  продажа игроком пополняет казну. Казна не печатает деньги — только перераспределяет.
* Поэтому «нагреть» экономику можно только реальной торговлей: купить дешевле, продать дороже,
  либо создавать дефицит.

### Готовое поселение: ратуша, мастерские и подарки

Поселение **рождается уже построенным**: `instantTownHall=true`, и ратуша (а с ней площадь, лавка,
склад и мастерские) ставится целиком в момент основания — стройка не нужна, `buildProgress` сразу
100%. Постепенная стройка осталась только как опция (`instantTownHall=false` + `autoBuild=true`).

Что появляется вместе с ратушей (`starterWorkshops=true`), и каждая постройка привязана к своей
профессии через `Settlement.workSites` (сохраняется в NBT как `WorkSites`):

| Постройка | Где | Что даёт |
|---|---|---|
| **Ферма** | западнее площади, поле 13×9 | грядки `farmland(moisture=7)` со спелой пшеницей, забор, кадка с водой, домик. Фермер стоит в поле и производит пшеницу, плюс морковь/пшеницу сверх нормы |
| **Дом лесоруба** | северо-запад | избушка, поленница из брёвен, пни и саженцы вокруг. Лесоруб производит `oak_log` |
| **Шахта** | северо-восток | устье с площадкой, ствол на 4 блока вниз с лестницей и крепью, отвал, бытовка, а в породе вокруг — `iron_ore`/`coal_ore`/`copper_ore`. **Работает сама**: копать ничего не надо, шахтёр стоит у устья и производит `cobblestone`, а по шансу — `iron_ingot` и `coal` (`workshopYield`) |
| **Мастерская строителя** | восток | кузнечный стол, верстак, леса с фонарём, штабель камня и кирпича. Ратушу строить не нужно, поэтому строитель **растит посёлок**: он идёт на выбранный поселением участок и за 16 камня и 8 брёвен ставит новый жилой дом (`builderExpands`, `maxVillageHouses=8`) |

Каждая постройка стоит на **выровненной площадке** (`gradePad` → `padLevel` + `gradeColumn`):
холм срезается, яма досыпается, сверху газон или мостовая. На крутом склоне получается терраса
(пределы `MAX_CUT`/`MAX_FILL`), поэтому посёлок не превращается ни в плотину, ни в карьер, и ничего
не висит в воздухе.

Работают мастерские **сами**: `workshopStep` раз в цикл рынка (`marketIntervalTicks`) начисляет
продукт каждой постройки, если в поселении есть работник этой профессии, и столько же съедает сырьё —
нет сырья, мастерская встаёт, а спрос на ресурс подскочит на табличке нужд. Житель, который
дошёл до своей точки, даёт тот же прирост сверху (`CitizenBrain.handleWork`). В `/market_dump`
видно привязку: `работа miner: 10,-59,-33`.

**Подарок.** В торговом окне появилась кнопка «Подарить» (и Shift+ЛКМ по строке товара): предмет
забирается из твоего инвентаря, денег никто не берёт — житель кладёт его в свои запасы
(`carried`), получает настроение (`giftMoodPerItem`, +к `mood`), а ты — репутацию в поселении
(`giftReputationPerItem` за предмет). В ратуше подарок идёт прямо на склад поселения.
`/market_dump` показывает, что житель носит: Shift+ПКМ по нему.

**Деньги NPC — временно бесконечные** (`infiniteNpcMoney=true`): посёлку можно продавать сколько
угодно, «в казне не хватает монет» больше не появляется, казна при этом не тратится; зарплаты
жителям платятся всегда, и кошелёк жителя сам подкидывается до цены еды, поэтому NPC не голодают
и не отказывают в скупке. В `/market_dump` это помечено `казна=900м (бесконечная)`.
Чтобы вернуть нормальную экономику — поставь `infiniteNpcMoney=false` в `config/rl2dop.json`.


### Планировка деревни (как в ванильной)

Поселение больше не «коробка посреди расчищенной площадки». `SettlementBuilds.plan()` строит
деревню по плану, где всё связано дорогами, а рельеф подстроен под застройку:

| Что | Где (от точки ратуши) | Как |
|---|---|---|
| Площадь | квадрат 37×43, `x ±18`, `z -21..21` | выровнена, мощение `dirt_path` + гравий/твёрдый грунт, по углам фонарные столбы |
| Ратуша | центр | как раньше: два этажа, вход с юга, колокол, светло внутри |
| Главная улица | `z = 16`, вдоль `x -46..46` | 3 блока шириной, выровнена кусками по 8 блоков → идёт ступенями по склону, а не «в воздухе» |
| Рабочая улица | `z = -24` | к ней выходят двери мастерских |
| Поперечные улицы | `x = ±46` | замыкают обе улицы в кольцо, к ним примыкает переулок |
| Переулок 2-го ряда | `z = 30` | подъезд к дальним участкам |
| Жилые участки | 2 ряда: `z = 8` (x = ±20, ±32, ±44) и `z = 22` (x = ±26, ±38) | 10 участков, ближние к ратуше застраиваются первыми (`housePlots()` сортирует по расстоянию): дом 7×7 + двор с забором и калиткой на улицу + фонарь; `housePlots()`/`freePlot()` |
| Колодец | `x=5, z=9` | сруб с водой и навесом — центр площади |
| Таверна | `x=-13, z=-15` (двор ратуши) | стойка, столы со стульями, очаг, свет, нары наверху для приезжих, дверь на площадь |
| Пруд | `x=11, z=-15` | копается на блок ниже площади, песчаный берег, камыш, кувшинка, фонарь на берегу |
| Мастерские | ряд `z = -34`, `x = -30, -10, 10, 30` | ферма, лесопилка, шахта, мастерская строителя — каждая на своей площадке и со своей дорожкой к рабочей улице |

Уровень у поселения **один** — уровень ратуши: `gradePad()` срезает холм и досыпает яму до него,
поэтому дома, дворы, площадь и мастерские лежат в одной плоскости, а не «на разных высотах».
Исключение — улицы: `roadLevel()` позволяет им отходить от уровня до `ROAD_TILT` (4) блоков, и
дорога идёт мягкими ступенями по 8 блоков, подстраиваясь под склон, а не разравнивая его бульдозером.

Дорожки есть **у каждой двери**: `roads()` кладёт путь от крыльца каждого участка до улицы, от
выхода ратуши до главной улицы, от мастерских до рабочей улицы и дорожку к таверне/пруду. Если
дом ставится позже (`/house_add`, самострой) — путь к нему дорисовывает следующий план.

### Жизнь деревни: приезжие, вакансии, самострой

Всё это делает `VillageLife` — шаг, который вызывается из экономического такта (раз в
`marketIntervalTicks`), а не каждый тик:

* **Поселение само хочет строить дома.** `housingDemand()` считает, скольким жителям негде жить,
  поднимает спрос на `cobblestone`/`oak_log` (это видно на табличке нужд и в ценах) и выбирает
  свободный участок из плана (ближний к ратуше) → `settlement.houseGoal`. Строитель приходит на
  участок, и когда на складе есть `houseCostCobble` + `houseCostLogs`, дом встаёт, после чего
  `assignHomes` расселяет жителей. Мест в домах считается по кроватям: в доме живёт не больше
  `villagersPerHouse` жителей, остальные ночуют в таверне — поэтому бездомные есть всегда, пока
  посёлка не хватило на всех, и стройка не «засыпается». Если строителя нет — за топор садится тот, кто ждёт работу у таверны. Отключается
  ключом `selfBuildHouses=false`.
* **Вакансии.** Вакансия = постройка есть, а работника нет (`settlement.workSites` против
  `Settlement.jobs`); для большого поселения ищут ещё повара, торговца и стражу, а для
  самостроя — строителя. Безработные расходятся по вакансиям сами, в порядке выгодности
  (зарплата × спрос на продукт).
* **Переселенцы приходят сами.** Раз в `immigrationIntervalTicks`, днём, если есть где жить
  (`villagersPerHouse` на дом + места в таверне) или есть вакансия: на незанятую мастерскую
  приезжает сразу работник, иначе — «просто так», в таверну, ждать работу. Потолки —
  `maxSettlers` и общий `maxNpcsPerSettlement`. Вручную позвать гостей: `/settle_settlers [поселение] [n]`.
* **Таверна** — общий дом: тут ночуют без дома, тут ждут вакансию, тут же полуденный перерыв.
  Рядом с дверью висит **доска вакансий** (`SignBoards.KIND_JOBS`): кого ищут, сколько платят,
  «строим дом» или «домов хватает», сколько человек без работы. Поселению без таверны её ставит
  `/settle_tavern`.

### Распорядок дня жителей

Занятие (`CitizenActivity`) считается по игровому времени — это перенос ванильного
`Schedule`/`Activity` жителей (`work` → `meet` → `rest`) на нашу концепцию, с двумя добавками:
полуденный перерыв и ожидание работы. Занятие видно над головой жителя, в `Shift+ПКМ`-подсказке
и в `/npc_list`.

| Время дня | Что делает житель |
|---|---|
| `0 … dayWorkStart` (2000) | утро: выходит из дома и идёт к своему месту |
| `dayWorkStart … dayBreakStart` | работа на своей постройке |
| `dayBreakStart … +2000` (6000→8000) | **перерыв у таверны**: сходятся в одно место, покупают еду со склада ратуши, болтают (настроение +; нет еды −, зато спрос на хлеб +) |
| `… dayMeetStart` | снова работа |
| `dayMeetStart … +1500` (12000→13500) | **сходка у колокола** (ванильный «meet»): настроение +, мирный игрок рядом получает +1 репутации за такт |
| `… ночь` | идёт домой (`rest`), ночью — сон даже без команды |
| всюду для `unemployed` | ждёт работу у таверны, слоняется рядом, без дела настроение медленно падает |

На работе житель держится своего места в радиусе `workLeash` блоков (не уходит бродить по деревне)
и периодически переходит к соседней грядке/станку, вместо того чтобы стоять истуканом. Отключить
расписание целиком: `citizenSchedule=false` (тогда все рабочие часы — работа, ночь — сон).

### Постройки, дома и глава поселения

* `/settle_spawn` и `/settle_build` ставят **настоящие блоки**. Ратуша — 13×11, два этажа
  (зал 11×9 высотой в четыре блока + антресоль), балкон с колоколом, шпиль, крыльцо, стол совета,
  сундук казны, книжные полки; вокруг — рыночная площадь с тропами и фонарями, восточная лавка с
  прилавком и навесом, западный склад с ящиками, и **два жилых дома** (`starterHouses`).
* **Здание не висит в воздухе**: перед стройкой считается `platformLevel` — уровень самой высокой
  точки грунта во всём пятне застройки, площадка выравнивается, а если грунт ниже, фундамент
  достраивается столбцами вниз до коренной породы.
* **Вход всегда есть**: в южной стене три широких проёма — две двери (их не надо открывать, они
  не ломаются при постройке) и открытая арка посередине. Двери ставятся после пола и только там,
  где план разрешает проход, так что «стены вместо входа» больше нет.
* **Внутри просторно и светло**: потолок первого этажа на высоте 4 блоков, антресоль — над ней;
  окна в два ряда по бокам и сзади, в полу — морской фонарь, под потолком и на площади —
  висячие фонари. На втором этаже тоже светло за счёт балконных проёмов.
* `/house_add [settlement]` — **поставить ещё один жилой дом** в точке прицела (или под ногами):
  каркас 7×7 с дверью, окнами, крыльцом, крышей, сундуком, верстаком и фонарём. Дом записывается в
  `Settlement.houses`, и NPC сразу получают его как точку сна (`assignHomes`).
  Откатать — `/settle_build <id> reset` (перестраивает всё поселение с нуля).
* **Главой** поселения становится отдельный NPC (`Profession.MAYOR`, имя в табличке `Mayor`):
  он появляется сам, когда ратуша построена, стоит **у табличек** лицом в зал, не спит и не меняет
  профессию. ПКМ по нему открывает скупку, где **выкупается вообще всё** (включая то, что лавка
  не принимает), с надбавкой `mayorBuyBonus`, а **торг отключён** — на «торговаться» он отвечает
  «со мной торговаться незачем». Продать ему можно и из `/settle_mayor`-окна, купить у него нельзя
  («за товаром — в лавку»). `/settle_mayor [settlement] [remove]` — перевыбрать или снять главу.
* Таблички с нуждами стоят **внутри зала** у дальней стены (пока ратуши нет — на площади), текст
  товаров идёт через переводы `rl2dop.short.*`, то есть **по-русски** для русского клиента:
  «нужно для стройки: камень x164, бревно x131», «казна 8250м», «скупка +5%: хлеб 9м».
* Блоки ставятся только туда, где воздух, трава, песок, вода или камень. То, что построил игрок
  или деревня, **не ломается** — такой блок пропускается, и здание просто подстраивается под место.
* Стройка растёт постепенно: за один цикл рынка ставится `buildBlocksPerTick` блоков, прогресс
  виден в `/market_dump` (`постройка=42%`). Это не даёт просадки тиков на больших поселениях.
* Точка магазина (`/shop_marker`) при постройке автоматически привязывается к прилавку лавки,
  поэтому торговцы и NPC ходят к реальной лавке, а не к невидимой точке.
* **Потребности рождаются со стройкой, а не «с пустого места»**:
  - склад нового поселения заполняется лишь на долю `startStockFraction` (0.35) от целевого —
    остальное поселение и просит;
  - `SignBoards` считает нужды по дефициту склада + спросу NPC, поэтому при незавершённой стройке
    в заголовке так и написано — «нужно для стройки»;
  - каждая ставка стройки (`consumeBuildMaterials`) **съедает** `cobblestone` и `oak_log` со склада
    и поднимает на них спрос: пока идёт постройка, спрос на камень и брёвна реально растёт;
    если материалов нет — в лог пишется «поселению не хватает материалов для стройки».
  Текст пишет сервер раз в `displayRefreshTicks`; при смене склада/спроса таблички обновляются сами.

### Цена

```
целевая = clamp(base * (targetStock / stock)^elasticity * (1 + спрос/100), min, max)
цена    = цена + (целевая − цена) * smoothing      // анти-скачок
покупка = ceil(цена * (1 + buySpread) * repFactor * торг)
скупка  = floor(цена * (1 − sellSpread) * repFactor * торг)
repFactor = 1 − rep/100 * 0.15                     // хороший дешевле, злой дороже
```

* Спрос (`demand`) растёт, когда игроки и NPC покупают, и медленно спадает каждый цикл рынка.
* Каждый цикл — раз в `marketIntervalTicks` (по умолчанию 100 тиков = 5 с).
* Все коэффициенты зажаты в min/max, поэтому цены не «улетают».

### Жизненный цикл NPC

```
работа на точке → произведено в сток → зарплата из казны (раз в salaryPeriodTicks)
        ↓                                          ↓
  голод < 35 → идёт в магазин → покупает хлеб (деньги уходят в казну)
        ↓
  ночь → идёт домой и спит; днём — снова на работу
        ↓
  автосмена профессии: только если есть ≥2 вакансии и выгода ≥ порога (cooldown 1200 тиков)
```

Стража: если репутация игрока ≤ `evilReputation` (−30), стражники **персонально** атакуют его
(мечники — в ближнем бою, лучники — стрелами). Агрессия не переходит на команду/других игроков.

### Анти-дюп

* Торговый экран — это **не** контейнер: клиент присылает только «товар + количество + действие».
* Сервер каждый раз заново проверяет: дистанцию до NPC, кулдаун (`tradeCooldownMs`), наличие
  монет, наличие предметов, сток, казну. Ни одно поле клиента не считается истиной.
* Продажа не может создать деньги: сумма выплаты ограничена казной.
* Покупка не может создать предметы: количество ограничено стоком.
* Записи в журнал (`/econ_log`) фиксируют каждую операцию.

- [ ] Бесконечные деньги NPC: продать ратуше 10 стеков камня → казна не уменьшилась, отказа нет.

- [ ] Глава: `/settle_mayor` → ПКМ по нему → продаётся ЛЮБОЙ товар (даже `sellable=false`),

- [ ] Дома: `/house_add` → дом на грунте, `settle_mayor`/`npc_list` → жители без дома получили
  точку сна в новом доме; `settle_build <id> reset` перестраивает поселение заново.
- [ ] Таблички: выкупить весь хлеб у ратуши → через несколько секунд на табличке `нужно` появится хлеб.
- [ ] Два и более игрока: у каждого свои монеты и своя репутация; торговые операции не смешиваются.
- [ ] Перезапуск сервера: цены/казна/сток те же, NPC на своих точках.
- [ ] Дюп через экран: спам кнопками → упирается в кулдаун, сток и казну.
- [ ] Смерть NPC: кошелёк выпадает монетами, NPC исчезает из списка поселения.
- [ ] Злой игрок: стража атакует только его, второго игрока рядом не трогает.
- [ ] Уход чанков: NPC догоняет расписание после возврата (ИИ тикает по глобальному времени).
- [ ] 4 игрока и 30+ NPC: TPS не проседает (ИИ раз в 10 тиков, рынок раз в 5 с).

## Проверка в CI

На каждый push GitHub Actions делает две вещи
([.github/workflows/build.yml](.github/workflows/build.yml)):

1. **build** — компилирует мод и публикует jar в release `latest`.
2. **smoke** — поднимает настоящий выделенный сервер (`./gradlew runServer`), заходит в консоль
   и прогоняет экономику целиком:

   ```
   /settle_spawn SmokeTown      → поселение, ратуша 100%, 2 стартовых дома, глава, таблички
   /settle_build                → мгновенная перестройка (пол по грунту, вход с дверями)
   /settle_mayor                → глава: стоит у табличек, скупает всё без торга (+5%)
   /house_add                   → ещё один жилой дом, точка сна для жителей
   /give_coins 500              → эмиссия 500/100000 (в казну)
   /spawn_npc farmer|trader|guard|cook → 4 NPC живут и работают
   /market_dump                 → цены/сток/спрос считаются
   /salary_set, /price_set, /shelf_add, /hall_board, /shop_marker, /npc_profession
   stop                         → мир сохраняется
   ```

   Отдельно проверяется, что стройка не закапывает жителей (`rescueBuried`) и что в логе
   нет `ERROR`/исключений — `smoke` падает на `погиб: inWall` только если точки снова
   окажутся внутри блоков.

   Затем сервер поднимается **второй раз** на том же мире, и проверяется, что
   `rl2dop_economy.dat` прочитался, казна/сток/цены/NPC на месте, а NPC помнят профессию.

Логи обоих запусков коммитятся в `ci/` только при падении (чтобы их можно было разобрать).

## Сборка из исходников

```bash
./gradlew build        # jar в build/libs
./gradlew runClient    # клиент для разработки
./gradlew runServer    # сервер
```

CI собирает каждый push и публикует jar в release `latest`
([.github/workflows/build.yml](.github/workflows/build.yml)).

Стек: Fabric Loader 0.20.1, Fabric API 0.116.17+1.21.1, Loom 1.19-SNAPSHOT,
официальные маппинги Mojang, Java 21, раздельные source set'ы `main` (общая логика) и
`client` (рендер, экран, HUD).
