# Rl2dop — экономика поселений для Minecraft 1.21.1 (Fabric)

Мод про живую экономику: одна монета, рынок с плавающими ценами, NPC с профессиями,
казна и ратуша, репутация и стража. Всё считается **на сервере**, клиент только рисует.

> **Статус:** собран по шагам 0–11 из техзадания. Мирогенерация и «красивая» генерация
> поселений не начаты намеренно (по плану — в самом конце), вместо неё привязка к ванильным
> деревням командой `/settle_bind`.

### Установка

1. Minecraft **1.21.1**, [Fabric Loader](https://fabricmc.net/use/installer/) ≥ 0.16.
2. Положить в `.minecraft/mods`:
   - `rl2dop-0.1.0.jar` (из ссылки выше),
   - [Fabric API](https://modrinth.com/mod/fabric-api) для 1.21.1.
3. Запустить. При первом старте создаётся `config/rl2dop.json`.

Сервер: то же самое, мод нужен и на сервере, и на клиенте (есть HUD и торговый экран).

## Быстрый старт (2 минуты)

```mcfunction
/settle_spawn Тестовый_город     # ратуша + поселение в текущей точке
/settle_bind                     # ИЛИ привязка к ванильной деревне (ищет колокол в 48 блоках)
/give_coins 200                  # напечатать монеты (с учётом лимита эмиссии)
/spawn_npc farmer                # заспавнить фермера
/spawn_npc trader Ганс           # торговец с именем
/shop_open                       # открыть торговый экран (или ПКМ по торговцу)
/market_dump                     # что с ценами
```

Дальше просто подожди: фермер носит зерно на склад, повар печёт хлеб из зерна,
торговец продаёт, стража получает зарплату из казны, NPC покупают еду и тратят монеты.

Уровень прав указан в скобках (2 = оператор, 3 = только для полного админа).

| `/set_reputation <player> <value>` (2) | репутация игрока в ближайшем поселении (−100…100) |

| `/reset_economy confirm` (3) | обнулить экономику |
| `/salary_set <profession> <amount>` (2) | зарплата профессии из казны |
| `/price_set <item> <base>` (2) | базовая цена товара |
| `/shop_open` | открыть торговый экран (торговец рядом или ратуша) |

| `/hall_board` (2) | поставить/обновить табло ратуши |
| `/npc_list` (2) | список NPC рядом: профессия, состояние, кошелёк, голод |

Профессии: `farmer`, `trader`, `guard`, `lumberjack`, `cook`, `miner`, `rancher`, `craftsman`,

## Как работает экономика

### Деньги

* `rl2dop:coin` — физический предмет. Монеты лежат в инвентаре игрока, у NPC — в кошельке-числе.
* **Эмиссия** (`minted`) считается в `EconomyState` и ограничена `mintLimit` из конфига.
  Напечатать больше лимита нельзя — `/give_coins` просто выдаст меньше.
* Казна поселения — отдельный счёт в `Settlement#treasury`. Зарплаты и скупка идут **из казны**,
  продажа игроком пополняет казну. Казна не печатает деньги — только перераспределяет.
* Поэтому «нагреть» экономику можно только реальной торговлей: купить дешевле, продать дороже,
  либо создавать дефицит.

### Цена

```
целевая = clamp(base * (targetStock / stock)^elasticity * (1 + спрос/100), min, max)
цена    = цена + (целевая − цена) * smoothing      // анти-скачок
покупка = ceil(цена * (1 + buySpread) * repFactor * торг)
скупка  = floor(цена * (1 − sellSpread) * repFactor * торг)
repFactor = 1 − rep/100 * 0.15                     // хороший дешевле, злой дороже
```

* Спрос (`demand`) растёт, когда игроки и NPC покупают, и медленно спадает каждый цикл рынка.
* Каждый цикл — раз в `marketIntervalTicks` (по умолчанию 100 тиков = 5 с).
* Все коэффициенты зажаты в min/max, поэтому цены не «улетают».

### Жизненный цикл NPC

```
работа на точке → произведено в сток → зарплата из казны (раз в salaryPeriodTicks)
        ↓                                          ↓
  голод < 35 → идёт в магазин → покупает хлеб (деньги уходят в казну)
        ↓
  ночь → идёт домой и спит; днём — снова на работу
        ↓
  автосмена профессии: только если есть ≥2 вакансии и выгода ≥ порога (cooldown 1200 тиков)
```

Стража: если репутация игрока ≤ `evilReputation` (−30), стражники **персонально** атакуют его
(мечники — в ближнем бою, лучники — стрелами). Агрессия не переходит на команду/других игроков.

### Анти-дюп

* Торговый экран — это **не** контейнер: клиент присылает только «товар + количество + действие».
* Сервер каждый раз заново проверяет: дистанцию до NPC, кулдаун (`tradeCooldownMs`), наличие
  монет, наличие предметов, сток, казну. Ни одно поле клиента не считается истиной.
* Продажа не может создать деньги: сумма выплаты ограничена казной.
* Покупка не может создать предметы: количество ограничено стоком.
* Записи в журнал (`/econ_log`) фиксируют каждую операцию.

## Конфиг `config/rl2dop.json`

Создаётся при первом запуске, правки подхватываются при перезапуске сервера.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `mintLimit` | `100000` | максимум напечатанных монет |
| `buySpread` / `sellSpread` | `0.15` / `0.10` | наценка магазина и дисконт скупки |
| `shopRange` | `10.0` | максимальная дистанция торговли |
| `tradeCooldownMs` | `300` | анти-спам на торговые действия |
| `marketIntervalTicks` | `100` | как часто пересчитывать рынок |
| `priceSmoothing` | `0.30` | скорость подстройки цены (0.01…1.0) |
| `demandDecayPerCycle` | `2` | как быстро остывает спрос |
| `brainIntervalTicks` | `10` | тик ИИ NPC (не каждый тик!) |
| `salaryPeriodTicks` | `2400` | период зарплаты |
| `autoProfessionCooldownTicks` | `1200` | cooldown автосмены профессии |
| `autoProfessionGain` | `1.25` | порог выгоды для смены (+25%) |
| `evilReputation` | `-30` | с этой репутации стража атакует |
| `shopRefuseReputation` | `-60` | торговец отказывает в обслуживании |
| `npcHitReputationPenalty` | `5` | штраф репутации за удар по NPC |
| `settlementRadius` | `96` | радиус, в котором игрок считается «в поселении» |
| `goods` | 12 товаров | `item`, `base`, `min`, `max`, `targetStock`, `elasticity`, `sellable` |
| `salaries` | 10 профессий | зарплата за период |

## Сохранения

| Файл | Что внутри |
|---|---|
| `world/data/rl2dop_economy.dat` | эмиссия, поселения (казна, склад, цены, спрос, зарплаты, репутация, ID NPC, полки), журнал |
| NBT каждого NPC | профессия, имя, кошелёк, голод, состояние, поселение, дом/работа/магазин, переносимый инвентарь |

NPC помечены как `setPersistenceRequired()`, поэтому переживают перезагрузку мира, выгрузку
чанков и перезаход игрока: профессия и рабочая точка читаются из NBT.

## Тесты вручную (чек-лист из ТЗ)

- [ ] Перезаход игрока: монеты и репутация сохраняются, HUD не мигает.
- [ ] Два и более игрока: у каждого свои монеты и своя репутация; торговые операции не смешиваются.
- [ ] Перезапуск сервера: цены/казна/сток те же, NPC на своих точках.
- [ ] Дюп через экран: спам кнопками → упирается в кулдаун, сток и казну.
- [ ] Смерть NPC: кошелёк выпадает монетами, NPC исчезает из списка поселения.
- [ ] Злой игрок: стража атакует только его, второго игрока рядом не трогает.
- [ ] Уход чанков: NPC догоняет расписание после возврата (ИИ тикает по глобальному времени).
- [ ] 4 игрока и 30+ NPC: TPS не проседает (ИИ раз в 10 тиков, рынок раз в 5 с).

## Сборка из исходников

```bash
./gradlew build        # jar в build/libs
./gradlew runClient    # клиент для разработки
./gradlew runServer    # сервер
```

CI собирает каждый push и публикует jar в release `latest`
([.github/workflows/build.yml](.github/workflows/build.yml)).

Стек: Fabric Loader 0.20.1, Fabric API 0.116.17+1.21.1, Loom 1.19-SNAPSHOT,
официальные маппинги Mojang, Java 21, раздельные source set'ы `main` (общая логика) и
`client` (рендер, экран, HUD).
